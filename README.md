# ⛳ 원온 미니골프 (ONEOINE MINI GOLF)

원온 홍보·이벤트용 **3D 클럽하우스 + 3홀 미니골프 웹앱 MVP**입니다.
회원 연동 없이 닉네임과 캐릭터 색상만 고르면 **3D 대기실(클럽하우스 광장)** 에 들어가고,
광장에서 사람들을 만나 **이모지로 인사**한 뒤 빛나는 **플레이룸 게이트**로 들어가면 3홀 라운드가 시작됩니다.
홀인원·버디 같은 이벤트를 달성하면 (다음 단계에서) 원온 앱에 등록할 수 있는 쿠폰 번호를 지급하는 구조를 염두에 두고 만들었습니다.

> 현재 버전은 **쿠폰 기능 제외** 상태입니다. 대기실·이모지 소통·플레이룸(3홀)·기록·공유·탭 간 실시간 동기화까지 구현했습니다.

- 스택: **Vite + TypeScript + Three.js + cannon-es**
- 외부 서버/API 키/오디오 파일 의존 없음 (효과음은 Web Audio로 실시간 합성)

## 1. 실행 방법

```bash
npm install
npm run dev        # http://localhost:5173
```

프로덕션 빌드:

```bash
npm run build      # tsc --noEmit + vite build → dist/
npm run preview    # dist 결과물 미리보기 (http://localhost:4173)
```

`vite.config.ts` 의 `base: './'` 덕분에 `dist/` 폴더를 GitHub Pages, S3, 사내 CDN 등
**어느 정적 호스팅에 올려도 그대로 동작**합니다. (서버 라우팅 불필요)

### 배포 예시 — GitHub Pages

```bash
npm run build
npx gh-pages -d dist      # 또는 dist/ 내용을 pages 브랜치에 푸시
```

## 2. 입장 흐름과 조작법

```
랜딩(닉네임·색상) → 3D 대기실(클럽하우스 광장) → 🌀 플레이룸 게이트 → 3홀 미니골프 → 스코어카드 → 🏠 대기실
```

### 2-1. 대기실 (클럽하우스 광장)

밝은 잔디 광장에 연못·나무·벤치·클럽하우스 건물·가로등이 있고, 광장 끝에 **빛나는 플레이룸 게이트**가 있습니다.
채팅은 없고 **이모지(👋⛳🔥👏😂🎉)** 로만 감정을 주고받습니다.

| 동작 | PC | 모바일 |
| --- | --- | --- |
| 이동 | `WASD` / `방향키` | 화면을 **드래그**(조이스틱) |
| 이동(포인트) | 바닥 **클릭** → 그쪽으로 걸어감 | 바닥 **탭** → 그쪽으로 걸어감 |
| 이모지 | 하단 이모지 바 클릭 (머리 위 말풍선 + 효과음) | 동일 |
| 플레이룸 입장 | 게이트로 걸어 들어가기 또는 `플레이룸 입장 ⛳` 버튼 | 동일 |
| 소리 / 도움말 | 우상단 🔊 / `?` | 동일 |

- 혼자 접속해도 **로비 게스트 4명**(버디헌터·핑크공·싱커·캐디)이 광장을 거닐며 가끔 이모지로 반응합니다.
- 내가 이모지를 보내면 근처 게스트가 잠시 뒤 같은/비슷한 이모지로 화답합니다.
- 같은 브라우저의 다른 탭에서 접속한 사람은 **위치·방향·이모지·플레이룸 이동**이 실시간으로 보입니다.

### 2-2. 플레이룸 (3홀 미니골프)

| 동작 | PC | 모바일 |
| --- | --- | --- |
| 퍼팅 | 공 근처에서 **마우스로 뒤로 드래그** 후 놓기 | **손가락으로 뒤로 드래그** 후 놓기 |
| 파워 | 드래그한 길이 (화면 하단 게이지) | 동일 |
| 방향 | 드래그 **반대 방향**으로 날아감 (슬링샷) | 동일 |
| 카메라 회전 | 마우스 **오른쪽 버튼 드래그**, `A`/`D`, `←`/`→` | **두 손가락 드래그** |
| 공 되돌리기 | `R` (+1벌타) | — |
| 소리 켜기/끄기 | `M` 또는 우상단 🔊 | 우상단 🔊 |
| 도움말 | `H` | 우상단 `?` |

- 에임 가이드: 당기는 동안 공 앞으로 점선과 링이 표시되고, 파워가 커질수록 길어지며 색이 초록→주황으로 변합니다.
- 샷을 마치면 카메라가 자동으로 공 뒤에서 컵 방향으로 정렬됩니다.

## 3. 코스 구성 (3홀)

| 홀 | Par | 이름 | 특징 |
| --- | --- | --- | --- |
| 1 | 2 | 스타트 라인 | 6.5m 직선. 사방이 뱅크월로 둘러싸여 튕겨서 방향을 바꿀 수 있는 워밍업 홀 |
| 2 | 3 | 코너 턴 | 오른쪽으로 90° 꺾이는 L자 코스. 코너 범퍼(돔) 3개 + 둥근 경사 범프를 넘거나 돌아가야 함 |
| 3 | 3 | 워터 브리지 | 좌우로 움직이는 장애물 → 워터 해저드 → 폭 1.4m 다리 순서로 통과. 물에 빠지면 직전 샷 위치로 복귀 +1벌타 |

- 홀인원 / 이글 / 버디 / 파 판정과 함께 **3D 컨페티 파티클 + 배너 + 효과음**이 재생됩니다.
- 홀당 최대 타수는 `Par + 4`. 넘으면 자동으로 기록하고 다음 홀로 넘어갑니다.
- 3홀을 모두 마치면 **스코어카드**(홀별 타수·성적·합계)와 `[다시 치기]`, `[기록 복사하기]`가 나옵니다.

## 4. 여러 탭에서 함께 (실시간 동기화)

이 MVP는 서버 없이 **BroadcastChannel** 로 같은 브라우저의 탭끼리 통신합니다.

1. 브라우저 탭을 2개 이상 엽니다. (같은 주소)
2. 각 탭에서 닉네임/캐릭터 색상을 다르게 정하고 **대기실 입장**을 누릅니다.
3. 대기실에서 서로의 **캐릭터 + 닉네임**이 보이고, 걷는 위치·이모지 말풍선이 실시간으로 동기화됩니다.
4. 한쪽이 플레이룸 게이트로 들어가면 다른 탭에서는 그 사람이 **⛳ 플레이룸**으로 표시되고, 플레이룸 안에서는 서로의 **반투명 공 + 닉네임 라벨**과 샷·홀인·이모지가 동기화됩니다. (같은 홀에 있는 플레이어만 코스에 렌더링)
5. 스코어카드의 `🏠 대기실로 돌아가기`로 대기실에 복귀하면 다시 광장에서 만납니다.

> 시크릿 창은 BroadcastChannel이 분리되어 서로 보이지 않습니다. 일반 탭 2개로 테스트하세요.

### 실제 서버로 교체하는 지점

`src/net/realtime.ts` 의 `Realtime` 인터페이스(`send` / `onMessage` / `close`)만 구현하면 전송 계층을 갈아 끼울 수 있습니다.
메시지는 모두 순수 JSON(`NetMessage`)입니다.

```ts
// 예: Supabase Realtime 어댑터로 교체
export function createRealtime(room: string): Realtime { /* ... */ }
```

| 후보 | 특징 |
| --- | --- |
| Supabase Realtime (Broadcast) | 무료 티어로 시작하기 쉽고, 추후 Auth/DB(쿠폰 발급)까지 한 곳에서 |
| Cloudflare Durable Objects + WebSocket | 방(room) 단위 상태를 서버가 들고 있어 순서/충돌 제어에 유리 |
| PartyKit / Ably / Firebase RTDB | 위 인터페이스로 감싸면 동일하게 사용 가능 |

서버로 옮길 때 추가로 필요한 것: 방 코드 입장, 발신자 인증(닉네임 위조 방지), 레이트 리밋,
그리고 **쿠폰 번호 발급은 반드시 서버에서 검증 후 발급**.

## 5. 쿠폰 기능을 붙일 때 (다음 단계 메모)

이번 범위에서는 제외했지만, 구조상 아래 지점에 붙이면 됩니다.

1. **이벤트 트리거 정의** — `Game`의 `onHoled(holeIndex, strokes, label)` / `onFinish(result)` 콜백이 이미 있습니다.
   예: `홀인원 1회 이상`, `3홀 합계 Par 이하`, `전체 9타 이하` 등.
2. **보상 요청** — `src/net/realtime.ts` 에 `"claim"` 메시지를 추가하고 서버(Edge Function 등)에서 검증 후
   원온 앱에서 등록 가능한 쿠폰 코드를 발급·응답.
3. **표시** — 스코어카드 하단에 쿠폰 번호 + 복사 버튼 추가 (`resultToText` 와 같은 방식).
4. **중복 방지** — 브라우저 로컬 저장(`localStorage`)은 우회 가능하므로 쿠폰은 서버 측 1회 발급 + 사용 이력 관리.

## 6. 프로젝트 구조

```
oneone_minigolf/
├─ index.html                 # HUD/입장/스코어카드 오버레이 마크업
├─ src/
│  ├─ main.ts                 # 부트스트랩, 두 씬(대기실/플레이룸), 화면 모드 전환, UI 이벤트
│  ├─ style.css               # 밝고 경쾌한 UI 스타일
│  ├─ lobby/
│  │  ├─ lobby.ts             # 3D 클럽하우스 광장·게이트·게스트·이동·이모지·로비 동기화
│  │  └─ avatar.ts            # 골퍼 캐릭터, 닉네임 라벨, 이모지 말풍선 스프라이트
│  ├─ game/
│  │  ├─ game.ts              # 게임 상태머신·퍼팅·스코어·네트워크 메시지 처리
│  │  ├─ course.ts            # 홀 3D 메쉬 + 물리 바디 생성, 컵/깃발/물/무버 연출
│  │  ├─ courses.ts           # 3홀 코스 데이터(좌표/장애물/장식)
│  │  ├─ physics.ts           # cannon-es 월드·재질·충돌 계수
│  │  ├─ camera.ts            # 공 추적 3인칭 카메라
│  │  ├─ effects.ts           # 컨페티/물보라 파티클, 떠오르는 이모지
│  │  ├─ audio.ts             # Web Audio 합성 효과음(외부 파일 없음)
│  │  ├─ scenery.ts           # 나무/바위/구름/공 메쉬
│  │  ├─ input.ts             # 포인터·키보드 입력
│  │  ├─ constants.ts         # 조작감/판정 튜닝 상수
│  │  └─ types.ts             # 코스/플레이어/라운드 타입
│  └─ net/
│     ├─ realtime.ts          # Realtime 어댑터 + BroadcastChannel 구현
│     └─ remotes.ts           # 다른 플레이어 공/닉네임 라벨 렌더링
```

## 7. 조작감 튜닝 포인트

`src/game/constants.ts`

| 상수 | 의미 |
| --- | --- |
| `MAX_SHOT_SPEED` / `MIN_SHOT_SPEED` | 풀파워/최소 파워 속도(m/s) |
| `AIM_MAX_DRAG_PX` | 풀파워가 되는 드래그 거리(px) |
| `CUP_RADIUS` / `CUP_ATTRACT_RADIUS` | 컵 판정 반경 / 빨려 들어가는 반경 |
| `STROKE_LIMIT_EXTRA` | 홀당 최대 타수 = Par + 값 |

`src/game/physics.ts` 의 `linearDamping`(공 감쇠)과 잔디 마찰로 굴러가는 거리가 정해집니다.
코스를 추가하려면 `src/game/courses.ts` 의 `HOLES` 배열에 항목을 추가하면 UI·진행·스코어카드가 자동으로 따라갑니다.

## 8. 검증

```bash
npx tsc --noEmit   # 타입 체크
npm run build      # 프로덕션 번들 생성 (dist/)
```

렌더러 없이 게임 로직만 돌려보는 헤드리스 점검 스크립트도 포함되어 있습니다.

```bash
npm run verify:physics   # 파워별 굴러가는 거리 측정 + 3홀 자동 플레이(컵 도달/물·OB/스코어 흐름)
npm run verify:sync      # 같은 방에 게임 2개를 붙여 참가자·위치·이모지 동기화 확인
npm run verify:lobby     # 대기실 2개를 붙여 이동·이모지·플레이룸 입장/복귀 동기화, 게스트 이동 확인
```

마지막 확인 결과 (참고):

- 파워 25% → 3.6m, 50% → 6.5m, 100% → 12.4m
- 자동 플레이: 1홀 홀인원 → 2홀 버디 → 3홀 더블보기 (합계 8타 / Par 8)
- 두 인스턴스가 서로의 입장·위치·이모지(🔥)를 정상 수신
- 대기실: 이동 동기화(1.9m/0.5초) · 게이트 도착 시 입장 트리거 · 플레이룸/대기실 인원 갱신 · 게스트 이동 확인

브라우저에서 실제 화면(3D 렌더링·터치 조작감)은 `npm run dev` 후 직접 확인하는 것을 권장합니다.
