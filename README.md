# ⛳ 원온 미니골프 (ONEOINE MINI GOLF)

원온 홍보·이벤트용 **3D 클럽하우스 + 3홀 미니골프 웹앱 MVP**입니다.
회원 연동 없이 닉네임과 캐릭터 색상만 고르면 **3D 대기실(클럽하우스 광장)** 에 들어가고,
광장에서 사람들을 만나 **이모지로 인사**한 뒤 빛나는 **플레이룸 게이트**로 들어가면 3홀 라운드가 시작됩니다.
홀인원·버디 같은 이벤트를 달성하면 (다음 단계에서) 원온 앱에 등록할 수 있는 쿠폰 번호를 지급하는 구조를 염두에 두고 만들었습니다.

> 현재 버전은 **쿠폰 기능 제외** 상태입니다. 대기실·이모지 소통·플레이룸(3홀)·기록·공유·**다른 기기/탭 간 실시간 동기화**까지 구현했습니다.

- **그래픽 룩 토글**: Synty 폴리 스타일 ↔ 실사 조명 기반 셀 셰이딩 카툰 스타일을 버튼 하나로 비교 (대기실·플레이룸 모두)

- 스택: **Vite + TypeScript + Three.js + cannon-es** + **Cloudflare Workers / Durable Objects**(실시간 동기화, `worker/`)
- 오디오 파일 의존 없음 (효과음은 Web Audio로 실시간 합성). 실시간 서버가 없어도 같은 브라우저 탭끼리는 그대로 동작합니다.

## 1. 실행 방법

```bash
npm install
npm run dev        # http://localhost:5173
```

프로덕션 빌드:

```bash
npm run build      # tsc --noEmit + vite build → dist/
npm run preview    # dist 결과물 미리보기 (http://localhost:4173)
```

**어느 정적 호스팅에 올려도 그대로 동작**합니다. (서버 라우팅 불필요)

### 배포 예시 — GitHub Pages

```bash
npm run build
npx gh-pages -d dist      # 또는 dist/ 내용을 pages 브랜치에 푸시
```

## 2. 입장 흐름과 조작법

```
랜딩(닉네임·색상) → 3D 대기실(클럽하우스 광장) → 🌀 플레이룸 게이트 → 3홀 미니골프 → 스코어카드 → 🏠 대기실
```

### 2-1. 대기실 (클럽하우스 광장)

밝은 잔디 광장에 연못·나무·벤치·클럽하우스 건물·가로등이 있고, 광장 끝에 **빛나는 플레이룸 게이트**가 있습니다.
채팅은 없고 **이모지(👋⛳🔥👏😂🎉)** 로만 감정을 주고받습니다.

| 동작 | PC | 모바일 |
| --- | --- | --- |
| 이동 | `WASD` / `방향키` | 화면을 **드래그**(조이스틱) |
| 이동(포인트) | 바닥 **클릭** → 그쪽으로 걸어감 | 바닥 **탭** → 그쪽으로 걸어감 |
| 이모지 | 하단 이모지 바 클릭 (머리 위 말풍선 + 효과음) | 동일 |
| 플레이룸 입장 | 게이트로 걸어 들어가기 또는 `플레이룸 입장 ⛳` 버튼 | 동일 |
| 소리 / 도움말 | 우상단 🔊 / `?` | 동일 |

- 혼자 접속해도 **로비 게스트 4명**(버디헌터·핑크공·싱커·캐디)이 광장을 거닐며 가끔 이모지로 반응합니다.
- 내가 이모지를 보내면 근처 게스트가 잠시 뒤 같은/비슷한 이모지로 화답합니다.
- 같은 브라우저의 다른 탭에서 접속한 사람은 **위치·방향·이모지·플레이룸 이동**이 실시간으로 보입니다.

### 2-2. 플레이룸 (3홀 미니골프)

| 동작 | PC | 모바일 |
| --- | --- | --- |
| 조준 | `A`/`D`, `←`/`→` 또는 화면 **좌우 드래그** | 화면 좌우 **드래그**, ◀ ▶ 버튼 |
| 뷰 전환 | `V` 또는 우상단 **🔭 뷰 전환** | 우상단 **🔭** 버튼 |
| 스윙(파워) | **스페이스바**·`Enter`를 **꾹 누르고 있다 떼기** 또는 `스윙!` 버튼/게이지 **꾹 눌렀다 떼기** | `스윙!` 버튼/게이지 **꾹 눌렀다 떼기** |
| 스윙(정확도) | 임팩트 존에서 **한 번 탭**(화면 아무 곳·`스페이스바`) | 임팩트 존에서 **한 번 탭** |
| 클럽 바꾸기 | 하단 클럽 칩 (1W·3W·5I·7I·9I·PW·SW·PT) | 동일 |
| 카메라 자유 시점 | 마우스 **오른쪽 버튼 드래그** | **두 손가락 드래그** |
| 공 되돌리기 | `R` (+1벌타) | — |
| 소리 켜기/끄기 | `M` 또는 우상단 🔊 | 우상단 🔊 |
| 플레이 가이드 / 도움말 | `H` 또는 우상단 `?` | 우상단 `?` |

- **첫 입장 가이드**: 플레이룸에 처음 들어가면 ① 조준·뷰 전환 ② 추천 클럽 ③ 꾹 눌러 파워·타이밍 탭을 3장으로 보여줍니다.
  한 번 보면 다시 뜨지 않고, 우상단 `?` 버튼으로 언제든 다시 볼 수 있어요.
- **스윙(홀드 & 릴리즈)**: `스윙!` 버튼이나 게이지를 **꾹 누르고 있는 동안** 파워 게이지가 0% → 100%로 차오르고,
  100%에 닿으면 다시 0% 쪽으로 내려가며 왕복합니다. **손을 떼는 순간(pointerup)의 게이지 위치가 파워로 확정**되고,
  이어서 게이지가 왼쪽 **임팩트 존**으로 돌아올 때 **한 번 탭**하면 정확도가 정해지며 샷이 나갑니다.
  존 한가운데를 맞추면 Perfect, 살짝 어긋나면 Good(훅/슬라이스), 크게 어긋나면 Miss예요.
  너무 짧게 눌렀다 뗀 실수 탭은 스윙이 되지 않고 준비 상태로 돌아갑니다. (`MIN_HOLD_SECONDS`)
- **뷰 전환**: `백뷰`(공 뒤) → `타겟뷰`(착지 예정 지점·그린 상공) → `탑뷰`(코스 전체)를 돌려 봅니다.
  타겟뷰에서는 착지 링과 그린·벙커·연못이 한눈에 들어와 파워를 가늠하기 좋습니다.
- **거리 표시**: HUD에 핀까지 **남은 거리**와 선택 클럽의 **최대 비거리(100%)**가 표시되고,
  누르고 있는 동안 **현재 파워 % · 예상 비거리**(예: `68% · 34.0m`)가 실시간으로 나옵니다.
  게이지 바에는 핀까지 필요한 파워 위치에 **🎯 목표 마커**가 찍힙니다.
- **에임 가이드**: 조준하는 동안 공 앞으로 점선 궤적·착지 링·정지 지점 링이 표시됩니다.
- **샷 후**: 골퍼는 샷을 친 자리에 그대로 서서 **공만 날아가는 걸** 지켜보고,
  공이 멈추면 새 공 옆으로 걸어가 어드레스 자세를 잡습니다.

### 2-4. 그래픽 룩 비교 (Synty 폴리 ↔ 카툰)

대기실과 플레이룸 모두에서 **홀 카드 아래 좌측 🎨 폴리 / 카툰** 버튼으로 그래픽 스타일을 바로 바꿔 볼 수 있습니다. 새로고침 없이 씬 전체가 전환되고, 선택은 `localStorage`(`oneone:look:v1`)에 저장되어 다음 방문에도 유지됩니다. (키보드 `L` 키로도 전환)

| 모드 | 특징 |
| --- | --- |
| **폴리** (기본) | Synty POLYGON 스타일 — 면마다 색이 갈리는 플랫 셰이딩 |
| **카툰** | 실사 조명·부드러운 그림자 위에 2~3단계 셀 셰이딩 + 하늘빛 프레넬 림라이트 + 얇은 네이비 외곽선. 곡면은 매끈한 버텍스 노멀로 이어지고, 상자 모서리 같은 45° 이상 꺾임은 그대로 남깁니다 |

구현은 `src/game/graphics.ts` 하나에 모였습니다.

- 매터리얼: `MeshStandardMaterial` → `MeshToonMaterial`(램프 텍스처) + `onBeforeCompile` 림라이트. 물·거품·반투명 링은 원래의 광택/투명도를 그대로 둡니다.
- 곡면: 같은 자리 정점의 노멀을 각도 가중으로 평균한 사본 지오메트리(원본은 그대로 보관, 필요할 때만 생성).
- 외곽선: 화면 공간 외곽선 패스(`OutlineEffect`) — 지면·물·UI성 메시는 `markGround()`/반투명 규칙으로 제외.
- 홀을 바꿔 새로 만든 코스나 새로 들어온 골퍼도 다음 동기화(프레임당 최대 20프레임에 한 번)에 자동으로 같은 룩을 입습니다. 한 번 바꾸는 비용은 홀+광장 합쳐 약 75ms(측정), 이후 동기화는 0.1ms 수준입니다.

## 4. 여러 기기에서 함께 (실시간 동기화)

실시간 동기화는 **두 겹**으로 동작합니다.

| 경로 | 대상 | 주소 |
| --- | --- | --- |
| **Cloudflare Worker + Durable Object WebSocket** | 다른 PC · 휴대폰 (인터넷 너머) | `wss://oneone-minigolf-sync.a810-glenn.workers.dev/ws?room=<room>` |
| **BroadcastChannel** | 같은 브라우저의 탭끼리 (오프라인·로컬 개발) | 브라우저 내부 채널 |

두 경로로 같은 메시지가 도착할 수 있어서, 메시지마다 붙인 `mid` 로 **한 번만** 처리합니다(중복 self-echo 방지).

- 방(room)은 두 개로 나뉩니다. **`lobby`** = 3D 대기실, **`play-1`** = 3홀 플레이룸.
  서버에서는 방 하나가 Durable Object 하나이고, 대기실 소켓은 플레이 중에도 살아 있어서
  누가 플레이룸에 있는지가 대기실 인원에 계속 반영됩니다.
- 연결이 끊기면 지수 백오프(0.5s → 최대 20s)로 다시 붙습니다.
- 서버가 알려주는 접속자 수·연결 상태는 HUD 오른쪽 위 칩(`🟢 3명` · `🟡 연결 중` · `⚪ 로컬` · `⚫ 오프라인`)에 표시됩니다.

### 확인 방법

1. 기기(또는 브라우저) 두 대에서 같은 주소를 엽니다.
2. 각자 닉네임/캐릭터 색상을 다르게 정하고 **대기실 입장**을 누릅니다.
3. 대기실에서 서로의 **캐릭터 + 닉네임**이 보이고, 걷는 위치·이모지 말풍선이 실시간으로 동기화됩니다.
4. 한쪽이 플레이룸 게이트로 들어가면 다른 쪽에서는 **⛳ 플레이룸**으로 표시되고,
   플레이룸 안에서는 서로의 **반투명 공 + 닉네임 라벨**과 샷·홀인·이모지가 동기화됩니다. (같은 홀에 있는 플레이어만 코스에 렌더링)
5. 스코어카드의 `🏠 대기실로 돌아가기`로 복귀하면 다시 광장에서 만납니다.

> 시크릿 창은 BroadcastChannel이 분리되어 탭끼리는 서로 보이지 않습니다. 이때는 서버 경로로만 만납니다.

### 서버 주소 바꾸기 / 끄기

| 방법 | 예 |
| --- | --- |
| 빌드 환경변수 | `VITE_WS_URL=wss://내서버/ws npm run build` |
| 주소 쿼리 | `?ws=wss://oneone-minigolf-sync.a810-glenn.workers.dev/ws`, `?ws=off` |
| 로컬 개발(`npm run dev`) | 기본은 서버에 붙지 않음(탭 간 동기화만). 배포 서버에 붙여 보려면 `?ws=wss://…` |

## 4-1. 실시간 서버 (Cloudflare Workers + Durable Objects)

`worker/` 폴더에 있습니다. **Workers Free 플랜**에서 그대로 돌아가도록 만들었습니다.

- **SQLite 기반 Durable Object**(`new_sqlite_classes = ["GolfRoom"]`) — 무료 플랜에서 KV 기반 DO는 배포되지 않습니다.
- **WebSocket Hibernation API**(`ctx.acceptWebSocket`, `webSocketMessage/Close/Error`, `serializeAttachment`) — 아무도 접속하지 않으면 Duration 한도를 쓰지 않습니다.
  마지막 상태는 attachment 에 보관해서, DO가 잠들었다 깨어나도 신규 입장자에게 접속자 스냅샷을 그대로 줄 수 있습니다.
- `ping` → `pong` 은 `setWebSocketAutoResponse` 로 런타임이 처리합니다(DO를 깨우지 않음).
- 동시 접속 상한: 방당 64, 프레임 상한: 16KB.

### 배포

```bash
cd worker
npm install
npx wrangler deploy        # 로그인되어 있거나 CLOUDFLARE_API_TOKEN 환경변수가 있으면 바로 배포
```

`worker/wrangler.toml` 에 계정·이름이 박혀 있습니다.

```toml
name = "oneone-minigolf-sync"                                  # → https://oneone-minigolf-sync.a810-glenn.workers.dev
account_id = "b02f6f589253271f1dafef3639f7c2ee"
compatibility_date = "2026-11-01"
workers_dev = true
```

### 엔드포인트

| 엔드포인트 | 설명 |
| --- | --- |
| `GET /health` | 200 OK + 서비스 정보 |
| `GET /rooms/:room` | 그 방의 현재 접속자 수 (WebSocket 없이 확인) |
| `GET /ws?room=<room>` · `GET /ws/<room>` | WebSocket 업그레이드 (방 없으면 `lobby`) |

방 이름은 `[A-Za-z0-9][A-Za-z0-9_-]{0,31}`.

### 메시지 프로토콜

게임 메시지(`NetMessage`)는 워커가 해석하지 않고 같은 방 전원에게 **발신자만 빼고** 그대로 중계합니다.

| 방향 | 프레임 |
| --- | --- |
| → 서버 | `{t:'msg', mid, msg}` · `{t:'ping', ts}` · `{t:'sync'}` |
| ← 클라이언트 | `{t:'ready', room, id, count, peers[]}` · `{t:'msg', mid, from, msg}` · `{t:'presence', room, count}` · `{t:'left', id}` · `{t:'pong'}` |

`ready.peers[]` 는 신규 입장자에게 보내는 **현재 접속자 스냅샷**(각 소켓이 마지막으로 보낸 `hello`/`state`/`lobby` 메시지)입니다.
`left` 를 받으면 클라이언트가 `bye`/`lobby-bye` 로 바꿔 처리하므로, 나간 사람이 20초 타임아웃까지 남아 있지 않습니다.

### 다음 단계 (보안·운영)

쿠폰 발급을 붙일 때를 대비해 서버로 옮겨야 하는 것: 발신자 인증(닉네임/점수 위조 방지),
방 코드 기반 입장 제한, 레이트 리밋, **쿠폰 번호는 반드시 서버에서 검증 후 1회 발급**.

## 5. 쿠폰 기능을 붙일 때 (다음 단계 메모)

이번 범위에서는 제외했지만, 구조상 아래 지점에 붙이면 됩니다.

1. **이벤트 트리거 정의** — `Game`의 `onHoled(holeIndex, strokes, label)` / `onFinish(result)` 콜백이 이미 있습니다.
   예: `홀인원 1회 이상`, `3홀 합계 Par 이하`, `전체 9타 이하` 등.
2. **보상 요청** — `src/net/realtime.ts` 에 `"claim"` 메시지를 추가하고 서버(Edge Function 등)에서 검증 후
   원온 앱에서 등록 가능한 쿠폰 코드를 발급·응답.
3. **표시** — 스코어카드 하단에 쿠폰 번호 + 복사 버튼 추가 (`resultToText` 와 같은 방식).
4. **중복 방지** — 브라우저 로컬 저장(`localStorage`)은 우회 가능하므로 쿠폰은 서버 측 1회 발급 + 사용 이력 관리.

## 7. 조작감 튜닝 포인트

`src/game/constants.ts`

| 상수 | 의미 |
| --- | --- |
| `GAUGE_POWER_SECONDS` / `GAUGE_IMPACT_SECONDS` | 게이지가 0→100%로 차오르는 시간(이후 같은 시간으로 왕복) / 임팩트 존으로 돌아오는 시간 |
| `MIN_HOLD_SECONDS` / `MIN_POWER` | 이보다 짧게 떼면 실수 탭으로 취소 / 떼는 순간 확정되는 최소 파워 |
| `MIN_POWER_RATIO` | 0% 파워에서도 나가는 속도 비율 |
| `CUP_RADIUS` / `CUP_ATTRACT_RADIUS` | 컵 판정 반경 / 빨려 들어가는 반경 |
| `STROKE_LIMIT_EXTRA` | 홀당 최대 타수 = Par + 값 |

클럽별 비거리·탄도는 `src/game/clubs.ts` 의 `loft`·`speed`(풀파워 발사 속도)로 정해지고,
파워→비거리 환산 지수(`DISTANCE_EXPONENT`)가 HUD 예상 비거리와 🎯 목표 마커에 쓰입니다.
클럽을 고친 뒤에는 `npm run verify:physics` 로 캐리/총비거리 실측을 다시 확인하세요.

`src/game/physics.ts` 의 `linearDamping`(공 감쇠)과 잔디 마찰로 굴러가는 거리가 정해집니다.
코스를 추가하려면 `src/game/courses.ts` 의 `HOLES` 배열에 항목을 추가하면 UI·진행·스코어카드가 자동으로 따라갑니다.

## 8. 검증

```bash
npx tsc --noEmit   # 타입 체크
```

렌더러 없이 게임 로직만 돌려보는 헤드리스 점검 스크립트도 포함되어 있습니다.

```bash
npm run verify:physics   # 번호별 클럽 비거리/탄도 + 추천 클럽 + 거리 모델 + 샷 후 골퍼 위치 + 뷰 전환 + 3홀 자동 플레이
npm run verify:swing     # 홀드&릴리즈 파워 확정 · 짧은 탭 취소 · Perfect/Good/Miss 판정 · 훅/슬라이스
npm run verify:sync      # 같은 방에 게임 2개를 붙여 참가자·위치·이모지 동기화 확인
npm run verify:lobby     # 대기실 2개를 붙여 이동·이모지·플레이룸 입장/복귀 동기화, 게스트 이동 확인
npm run verify:look      # 그래픽 룩 전환 — 카툰 매터리얼·매끈 노멀·외곽선 표시 규칙·폴리 복원
npm run verify:relay     # Durable Object 중계 로직 (발신자 제외·스냅샷·퇴장·방 분리·잘못된 프레임)
npm run verify:net       # 앱 ↔ 워커 프로토콜 (다른 기기 2대 가정, 중복 제거·재연결 포함)
```

마지막 확인 결과 (참고):

- 파워 25% → 3.6m, 50% → 6.5m, 100% → 12.4m
- 자동 플레이: 1홀 홀인원 → 2홀 버디 → 3홀 더블보기 (합계 8타 / Par 8)
- 두 인스턴스가 서로의 입장·위치·이모지(🔥)를 정상 수신
- 대기실: 이동 동기화(1.9m/0.5초) · 게이트 도착 시 입장 트리거 · 플레이룸/대기실 인원 갱신 · 게스트 이동 확인
